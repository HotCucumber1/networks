# 1. Описание алгоритма работы DNS-резолвера

Программа выполняет итеративное разрешение доменных имён. Её задача — получить DNS-записи домена, самостоятельно обращаясь к серверам DNS, начиная с корневых серверов, вместо того чтобы передавать весь запрос одному локальному DNS-резолверу.

При запуске пользователь указывает доменное имя и тип записи. Например, `A` используется для получения IPv4-адреса, а `AAAA` — для IPv6-адреса. Флаг `-d` включает режим отладки, в котором программа выводит подробности запросов и ответов, переходы между уровнями DNS и обработку ошибок.

**Основные этапы работы программы:**

1. Подготовка запроса. Программа разбирает аргументы командной строки, определяет тип записи и формирует DNS-пакет с уникальным идентификатором запроса. Флаг рекурсии `RD` отключён, поскольку разрешение выполняется самой программой.
2. Обращение к корневым серверам. Программа выбирает IP-адреса корневых DNS-серверов и отправляет запрос по UDP на порт 53.
3. Переход к следующему уровню. Если сервер не возвращает конечную запись, программа анализирует секции `Authority` и `Additional`. Из них она извлекает сведения о серверах следующей зоны и, если доступны, их IP-адреса. Затем запрос отправляется следующему подходящему серверу.
4. Получение результата. Когда найдены нужные записи, программа выводит их имя, TTL, класс, тип и значение. Также обрабатываются псевдонимы `CNAME`, ошибки DNS и ситуации, когда запись нужного типа отсутствует.
5. Кэширование. Полученные записи могут сохраняться в локальном файле. При повторном запросе программа проверяет срок действия записи и использует её из кэша, если TTL ещё не истёк.

В программе предусмотрены ограничения на количество шагов разрешения и глубину обработки цепочек `CNAME`, чтобы избежать бесконечных переходов.

## 2. Алгоритм автоматического перехода с UDP на TCP

Этот механизм нужен, когда DNS-ответ не помещается в UDP-пакет целиком. В заголовке DNS для этого предусмотрен флаг `TC` (Truncated).

В программе переключение выполняется следующим образом:

1. Резолвер отправляет DNS-запрос по UDP.
2. Получив ответ, он анализирует DNS-заголовок и проверяет флаг `TC`.
3. Если `TC` не установлен, программа продолжает обычный разбор полученного ответа.
4. Если `TC` установлен, программа выводит отладочное сообщение и повторяет тот же запрос к тому же DNS-серверу по TCP.
5. Для TCP-запроса перед DNS-сообщением добавляется двухбайтовый префикс длины пакета. При чтении ответа программа сначала получает эти два байта, определяет длину сообщения, а затем читает весь пакет.
6. Полученный ответ разбирается обычным DNS-парсером. Если соединение не удалось установить, сервер не ответил вовремя или пакет некорректен, программа сообщает об ошибке.

Таким образом, UDP используется как основной транспорт, а TCP — как автоматический резервный вариант при усечённом ответе. Для TCP и UDP в коде реализованы отдельные классы, что упрощает сопровождение программы.

Для запросов типа `DNSSEC` используется запрос записей `DNSKEY` с установленным флагом `DO` и ограничением UDP-размера в 512 байт. Это позволяет попробовать получить большой DNS-ответ и продемонстрировать переход на TCP. При этом программа запрашивает DNSSEC-связанные записи, но не выполняет полноценную криптографическую проверку DNSSEC-подписей.

## 3. Как скомпилировать программу

В терминале выполнить:

```
g++ -std=c++20 -O2 -Wall -Wextra -Wpedantic dns_resolver.cpp -o dns_resolver
```

Если компиляция завершилася без ошибок, программу можно запускать. 

## 4. Как запустить программу

### Обычное разрешение домена

```
./dns_resolver example.com A
```

Получение IPv6-адреса:

```
./dns_resolver example.com AAAA
```

В обычном режиме выводятся конечные DNS-записи без подробного описания сетевого обмена.

### Режим отладки

```
./dns_resolver example.com A -d
```

В этом режиме программа дополнительно показывает, к каким DNS-серверам обращается, какие ответы получает и как переходит от корневой зоны к следующим зонам.

### Проверка DNSSEC и перехода на TCP

```
./dns_resolver com DNSSEC -d
```

Этот запрос демонстрирует переход с UDP на TCP: программа запрашивает DNSKEY с включённым флагом `DO` и небольшим допустимым размером UDP-ответа. Однако появление `TC` зависит от фактического ответа DNS-сервера, поэтому переход не гарантирован при каждом запуске.

### Работа с кэшем

Показать сохранённые записи:

```
./dns_resolver --cache-show
```

Очистить кэш:

```
./dns_resolver --cache-clear
```

Кэш хранится в файле `.dns_resolver_cache` в текущем каталоге. Чтобы показать именно сетевое разрешение, перед демонстрацией можно очистить его:

```
./dns_resolver --cache-clear
./dns_resolver example.com A -d
```
