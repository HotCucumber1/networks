# Описание архитектуры проекта и инструкция по запуску

## 1. Архитектура проекта

Проект представляет собой клиент-серверное приложение на языке C, которое использует TCP-соединение для обмена сообщениями между клиентом и сервером.

Сервер принимает подключения клиентов, обрабатывает полученные сообщения и отправляет ответ. Для обработки нескольких соединений одновременно используется многопроцессная и многопоточная архитектура: сервер запускает несколько рабочих процессов, а каждый рабочий процесс использует пул потоков. Для обработки сетевых событий применяется механизм `epoll`.

Клиент отправляет серверу имя и числовое значение. Сервер разбирает сообщение, выполняет проверку данных и возвращает собственное имя и число. В процессе обработки сервер также ведёт статистику соединений, учитывает ошибки и контролирует время ожидания данных. Если клиент передаёт число за пределами допустимого диапазона, это может служить командой на завершение работы сервера.

Для повышения надёжности предусмотрены тайм-ауты, обработка сигналов, корректное завершение рабочих процессов и автоматический перезапуск некоторых аварийно завершившихся рабочих процессов. Также предусмотрена возможность запускать сервер в тихом режиме без подробных сообщений о каждом соединении.

## 2. Основные файлы проекта

- `server.c` — серверная часть: приём соединений, обработка сообщений, управление рабочими процессами и потоками, статистика и завершение работы.
- `client.c` — клиентская часть: подключение к серверу, отправка сообщения и получение ответа.
- `loadtest.c` — программа для нагрузочного тестирования сервера с большим количеством запросов и параллельных клиентов.
- `Makefile` — содержит правила сборки обычной версии программы, а также вариантов с AddressSanitizer и ThreadSanitizer.
- `demo.sh` — сценарий автоматической демонстрации работы программы: проверка обычных запросов, тайм-аутов, завершения сервера, нагрузки, ошибок памяти и перезапуска рабочих процессов.

Исполняемые файлы после сборки размещаются в каталогах `build`, `build-asan` и `build-tsan`.

## 3. Сборка программы

Для сборки необходимы Linux, компилятор GCC, утилита `make` и поддержка POSIX-потоков. Для запуска полного демонстрационного сценария также могут понадобиться `valgrind`, `nc` и другие стандартные утилиты.

Сначала нужно перейти в каталог проекта:

```
cd путь/к/проекту
```

Затем собрать основные программы:

```
make all
```

После успешной сборки в каталоге `build` должны появиться три исполняемых файла:

- `build/server`
- `build/client`
- `build/loadtest`

Дополнительно можно собрать версии для проверки ошибок памяти и многопоточности:

```
make asan
make tsan
```

`asan` используется для выявления некоторых ошибок работы с памятью, а `tsan` — для обнаружения потенциальных гонок данных в многопоточном коде.

Можно просто собрать через
```bash
mkdir -p build
gcc -O2 -g -std=c17 -Wall -Wextra -Wpedantic -Wshadow -Wformat=2 -Wvla client.c -o build/client -pthread
gcc -O2 -g -std=c17 -Wall -Wextra -Wpedantic -Wshadow -Wformat=2 -Wvla server.c -o build/server -pthread
gcc -O2 -g -std=c17 -Wall -Wextra -Wpedantic -Wshadow -Wformat=2 -Wvla loadtest.c -o build/loadtest -pthread
```

## 4. Запуск программы

Сначала необходимо запустить сервер в первом терминале:

```
./build/server
```

По умолчанию сервер использует TCP-порт `5555`. После запуска он выводит сообщение о запуске рабочих процессов и ожидает подключения клиентов.

Затем во втором терминале можно запустить клиент:

```
./build/client
```

Если клиент ожидает данные из стандартного ввода, их можно передать через `echo`:

```
echo 42 | ./build/client
```

В таком случае клиент получает число из ввода, отправляет запрос серверу и выводит ответ. Точный формат запроса и ответа определяется реализацией клиента и сервера.

Для остановки сервера можно нажать `Ctrl+C` в терминале, где он запущен. Сервер обрабатывает сигнал завершения и выполняет остановку рабочих процессов.

## 5. Дополнительные параметры сервера

При необходимости можно изменить параметры запуска сервера:

```
./build/server -p 5555 -P 2 -w 4 -t 10 -i 5
```

Здесь:

- `-p` — TCP-порт;
- `-P` — количество рабочих процессов;
- `-w` — количество потоков в каждом рабочем процессе;
- `-t` — тайм-аут обработки клиента в секундах;
- `-i` — интервал вывода статистики в секундах;
- `-q` — тихий режим, в котором подавляются подробные сообщения о соединениях.

Например, параметры `-P 2 -w 4` задают два рабочих процесса с четырьмя потоками в каждом.

## 6. Автоматическое тестирование

Для проверки основных возможностей проекта предусмотрен сценарий `demo.sh`. Его можно запустить из корневого каталога проекта:

```
chmod +x demo.sh
./demo.sh
```

Сценарий сначала собирает необходимые версии программ, а затем последовательно выполняет тесты. Среди них — проверка обычных запросов, тайм-аутов при медленной передаче данных, корректного завершения сервера, обработки высокой нагрузки, проверки памяти и перезапуска рабочего процесса после его аварийного завершения.

Результаты сохраняются в каталоге `output`. Если в терминале некоторое время ничего не отображается, это не обязательно означает зависание: сборка выполняется в тихом режиме, а вывод отдельных тестов перенаправляется в файлы.

Для просмотра результатов можно использовать:

```
ls -lh output/
```

А для просмотра содержимого конкретного отчёта, например:

```
cat output/01_basic.txt
```

Наличие отчётов означает, что сценарий записывал результаты тестов, но для подтверждения успешного прохождения нужно проверить их содержимое и убедиться, что выполнение скрипта завершилось без ошибок.

## 7. Итог

Проект демонстрирует работу TCP-клиент-серверного приложения на языке C с параллельной обработкой соединений. Сервер использует несколько процессов, пулы потоков и `epoll`, а также реализует тайм-ауты, статистику и обработку сигналов. Сборка выполняется с помощью `Makefile`, а проверка основных функций и устойчивости реализована в сценарии `demo.sh`.
